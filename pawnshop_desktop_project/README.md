# โปรแกรมสถานธนานุบาลเทศบาลเมืองกระบี่ — Windows Desktop

ชุดซอร์สสำหรับแพ็กไฟล์ HTML ต้นฉบับ `pawnshop_local_v4.html` เป็นโปรแกรม Windows 11 โดยใช้ Electron

## สิ่งที่ทำไว้ในโครงนี้

- นำหน้าเว็บและฟังก์ชันเดิมมาใช้ต่อ โดยไม่เปลี่ยนโครงสร้างข้อมูลของระบบบัญชี
- เก็บ LocalStorage และ IndexedDB ไว้ในโฟลเดอร์ข้อมูลผู้ใช้ของ Windows ซึ่งแยกจากโฟลเดอร์ติดตั้งโปรแกรม
- ปิดหน้าต่างด้วยปุ่ม X แล้วโปรแกรมย่อลง System Tray เพื่อรอตรวจ USB ต่อ
- ตั้งให้เริ่มตัวช่วยพร้อม Windows ได้
- เลือก USB เป้าหมายและตรวจจับการเสียบ USB เป็นช่วง ๆ
- สำรองไฟล์ JSON ลงเครื่องก่อน จากนั้นคัดลอกไป USB ที่เลือกเมื่อพบไดรฟ์
- ใช้ไฟล์รายวันและเก็บย้อนหลังไม่เกิน 30 ชุดต่อปลายทาง
- ตรวจ SHA-256 และเปิดอ่านไฟล์ที่เขียนจริงก่อนรายงานว่าสำรองสำเร็จ
- กู้คืนไฟล์สำรองของโปรแกรม โดยบันทึกจุดกู้คืนของข้อมูลปัจจุบันก่อน
- นำเข้า JSON แบบเดิมจากเว็บ v4 ผ่านฟังก์ชัน importJSON เดิมของระบบ
- เตรียมระบบตรวจสอบ/ดาวน์โหลดอัปเดตผ่าน GitHub Releases
- สร้าง Windows NSIS installer พร้อม Shortcut บน Desktop และ Start Menu

## สำคัญมากก่อนย้ายจากเว็บเดิม

ข้อมูลที่บันทึกในเว็บเดิมบน Vercel อยู่ใน LocalStorage ของ Origin เว็บนั้น ไม่ได้อยู่ในไฟล์ HTML และไม่สามารถถูกอ่านโดยโปรแกรม Windows อัตโนมัติได้

1. เปิดเว็บเดิมบนเบราว์เซอร์เครื่องที่มีข้อมูลล่าสุด
2. เปิดเมนู **ข้อมูล → สำรองระบบ (.json)** แล้วบันทึกไฟล์ JSON ไว้ในโฟลเดอร์ที่หาเจอง่าย
3. เก็บไฟล์นี้ไว้อีกชุด ห้ามลบข้อมูลเดิมในเว็บ
4. หลังติดตั้งโปรแกรม Windows เปิดโปรแกรมและปลดล็อกหน้าบัญชีด้วย PIN เดิมก่อน จากนั้นเปิดเมนู **ตั้งค่าโปรแกรม / USB**
5. กด **เลือกไฟล์ JSON จากเว็บเดิม** แล้วเลือกไฟล์ที่ส่งออกไว้
6. ตรวจสอบวันที่และรายการในโปรแกรมก่อนเริ่มใช้จริง

ฟังก์ชันนำเข้าต้นฉบับจะเก็บจุดกู้คืนก่อนแทนที่ข้อมูลเดิม แต่ควรเก็บไฟล์ส่งออกแยกไว้อีกชุดเสมอ

## วิธีสร้างตัวติดตั้งบน Windows 11

ต้องใช้ Windows 10/11 64-bit และเชื่อมต่ออินเทอร์เน็ตระหว่างติดตั้ง dependencies และดาวน์โหลดไลบรารีที่ใช้ในโปรแกรม

1. ติดตั้ง Node.js 24 LTS จากเว็บไซต์ทางการของ Node.js
2. แตกไฟล์โครงการนี้ลงโฟลเดอร์ เช่น `C:\PawnshopKrabiDesktop`
3. เปิด PowerShell ในโฟลเดอร์ดังกล่าว
4. รันคำสั่ง:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build-windows.ps1
```

5. เมื่อเสร็จ ไฟล์ติดตั้งจะอยู่ที่ `dist\Pawnshop-Krabi-Setup-1.1.0.exe`
6. เปิดไฟล์ติดตั้ง เลือกตำแหน่งติดตั้ง และทำตามขั้นตอน

หรือใช้คำสั่งแยก:

```powershell
npm install
npm run check
npm run dist:win
```

ก่อน Build โปรแกรมจะดาวน์โหลด Tailwind runtime และ PDF.js 3.11.174 มาไว้ใน `renderer/vendor` เพื่อให้ส่วนตกแต่งหน้าเว็บและอ่าน PDF ไม่ต้องเรียก CDN เหล่านั้นขณะใช้งาน

## ตั้ง USB สำรองอัตโนมัติ

1. เปิดโปรแกรม แล้วกด **ตั้งค่าโปรแกรม / USB** ที่มุมขวาบน หรือเปิดจากไอคอนถาดระบบใกล้นาฬิกา
2. เสียบ USB ที่ต้องการใช้สำรองข้อมูล
3. กด **ค้นหา USB อีกครั้ง**
4. เลือกไดรฟ์ USB แล้วกด **บันทึก USB นี้**
5. โปรแกรมจะสร้างโฟลเดอร์ `Pawnshop Krabi Backup` ที่ราก USB และสร้างไฟล์รายวัน เช่น `pawnshop_backup_2026-11-06.json`
6. เมื่อมีการบันทึกข้อมูล ระบบจะทำสำเนาในเครื่อง และคัดลอกไป USB ที่เลือกเมื่อ USB พร้อมใช้งาน
7. กด X เพื่อซ่อนหน้าต่างได้ ตัวโปรแกรมจะยังทำงานใน System Tray

หากปิดจากเมนู **ออกจากโปรแกรมทั้งหมด** หรือปิดโปรเซสจาก Task Manager ระบบตรวจจับ USB จะหยุดจนกว่าโปรแกรมจะเริ่มทำงานอีกครั้ง

### ตำแหน่งข้อมูลหลักใน Windows

`%APPDATA%\PawnshopKrabiLedger`

ข้อมูล LocalStorage, IndexedDB, ค่าตั้งค่า และไฟล์สำรองในเครื่องจะเก็บอยู่ในเส้นทางนี้ ไม่อยู่ในโฟลเดอร์ติดตั้ง การถอนการติดตั้งจึงไม่ลบข้อมูลในโฟลเดอร์ดังกล่าวตามการตั้งค่า installer

## ระบบอัปเดตในอนาคต

ตัวโปรแกรมรองรับ `electron-updater` และตั้งค่า Build ให้เผยแพร่ผ่าน GitHub Releases แต่ยังต้องมี Repository ของเจ้าของโปรแกรมก่อนเปิดใช้งานจริง

1. สร้าง GitHub repository สำหรับโครงการนี้ และแนะนำให้เป็น Public เพื่อให้เครื่องที่ติดตั้งโปรแกรมดาวน์โหลด Release ได้โดยไม่ต้องมี GitHub token
2. อัปโหลดซอร์สโครงการนี้ขึ้น repository
3. ในการปล่อยเวอร์ชันใหม่ ให้เพิ่มเลข `version` ใน `package.json` เช่น `1.0.1` แล้ว commit
4. สร้าง Git tag ให้ตรงกับเวอร์ชัน เช่น `v1.0.1` แล้ว Push tag
5. GitHub Actions จะ Build installer และเผยแพร่ไฟล์สำหรับ Auto Update
6. โปรแกรมที่ติดตั้งอยู่จะตรวจเวอร์ชันเมื่อเปิดโปรแกรมและดาวน์โหลดอัปเดตเมื่อมี Release ใหม่

ไฟล์ workflow อยู่ที่ `.github/workflows/windows-build.yml` โดยการกด Run workflow จะสร้าง artifact สำหรับทดสอบ ส่วนการ Push tag `v*` จะเข้าสู่ขั้นตอนเผยแพร่ Release

## หมายเหตุและข้อจำกัดที่ต้องทราบ

- ข้อมูลบัญชีเก็บเฉพาะในเครื่องนี้ ไม่มีเซิร์ฟเวอร์ฐานข้อมูล และไม่ส่งฐานข้อมูลไปออนไลน์
- การอัปเดตโปรแกรมทำผ่านอินเทอร์เน็ตและ GitHub Releases แต่ไม่ต้องอัปโหลดข้อมูลบัญชี
- Google Fonts (Sarabun) และ Font Awesome ยังอ้างอิง CDN ตามต้นฉบับ หากไม่มีอินเทอร์เน็ต ตัวหนังสือ/ไอคอนอาจใช้ฟอนต์สำรองหรือไม่แสดง แต่ฐานข้อมูลในเครื่องยังอยู่; Tailwind และ PDF.js ถูกเตรียมให้แพ็กเป็นไฟล์ local ตอน Build
- ตัวตรวจ USB ใช้ Windows WMI และมองหาไดรฟ์ที่ Windows รายงานเป็น Removable Disk (DriveType 2) อุปกรณ์ USB บางรุ่นที่แสดงเป็น Fixed Disk อาจไม่ปรากฏในรายการ
- เครื่องต้องเปิดอยู่และโปรแกรมตัวช่วยต้องทำงานอยู่ จึงจะตรวจพบการเสียบ USB ได้ หากปิดเครื่องจะเริ่มตรวจใหม่เมื่อเข้า Windows ครั้งถัดไป
- ไฟล์สำรองแต่ละวันจะถูกเขียนทับด้วย snapshot ล่าสุดของวันนั้น และเก็บย้อนหลัง 30 ไฟล์ต่อปลายทาง
- รหัส PIN ใน HTML ต้นฉบับเป็น `1234` และยังคงเดิมในชุดนี้ การล็อก PIN เป็นเพียงหน้ากั้นการใช้งาน ไม่ใช่การเข้ารหัสฐานข้อมูล
- การตรวจไวยากรณ์และโครงสร้างซอร์สไม่ได้ทดแทนการทดสอบบน Windows จริง ก่อนใช้ข้อมูลจริงควรทดสอบการติดตั้ง การปิดหน้าต่าง การเสียบ/ถอด USB การกู้คืน และการอัปเดตกับสำเนาข้อมูลก่อน

## โครงสร้างหลัก

- `renderer/index.html` — หน้าโปรแกรมต้นฉบับ v4 ที่นำมาใช้
- `renderer/desktop-integration.js` — สะพานเชื่อมกับ Electron โดยไม่ตัดฟังก์ชันเดิม
- `renderer/settings.html` / `settings.js` — หน้าตั้งค่าระบบ USB / restore / update
- `electron/main.js` — หน้าต่างโปรแกรม, System Tray, startup, IPC และ updater
- `electron/backup-manager.js` — สร้าง/ตรวจสอบ/กู้คืนไฟล์สำรอง
- `electron/usb-monitor.js` — ตรวจหา USB drive บน Windows
- `electron/preload.js` — API แบบจำกัดสิทธิ์ที่ส่งให้หน้าเว็บ
- `scripts/vendor-assets.mjs` — ดาวน์โหลดไลบรารีที่ต้องแพ็กไว้ในเครื่อง
